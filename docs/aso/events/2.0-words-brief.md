# Brief: words for Cutling 2.0's in-app event and release notes

card: ASG152 and ASG150 (board ~/Repositories/undirect/docs/plans/app-store-growth/BOARD.md; the session cutling-2-release owns the cards and commits)

## Goal

The English words a buyer reads about Cutling 2.0:

1. The In-App Event: an event name, a short description and a long description.
2. The App Store "What's New" text for 2.0 on iPhone and iPad, and the one for the Mac.
3. For every line above, a plain statement of what it must make the reader understand, in meaning and
   not in wording, so that writers in 49 other languages can each write their own line from it without
   ever seeing yours (the `blind-translation` skill; English is a peer language written the same way,
   not the source).

## Why it matters

The owner searched the App Store on his phone and saw no picture under Cutling. Since iOS 15, people
who already have an app see only its icon row in search; the one thing they do see is the app's In-App
Event card, which carries the event name and short description in white over the art, and opens a
details page with the long description. 2.0 is Cutling's biggest update. The What's New text is what
the App Store shows under the update, and what people read when deciding to open the app again.

## The owner's rule for buyer copy (word for word)

> Copy a buyer reads (App Store text, In-App Event descriptions, promo text, posts) leads with what the
> buyer gets: they read the article they opened, never land on a scam page, the Back button takes them
> back. Words from the maker's side ("caught", "blocked", "trap", "layer", "detects", "new tricks") are a
> feature exhibition and do not sell. Name the button in full: "Back button", never "Back".
>
> Why: the owner (2026-11-21) rejected four rounds of Undirect event text as feature exhibition that
> "will not attract customers at all", and says this keeps happening.
>
> How to apply: before writing or briefing any buyer-facing line, start from the buyer's own complaint
> (docs/research/undirect-voice-of-customer.md) and write what they wanted instead.

(The examples in that rule are Undirect's. Cutling's buyers' own complaints are in
`~/Repositories/undirect/docs/research/cutling-voice-of-customer.md`.) The owner approved Undirect's event
text in his own words: name "The Stay-Put Update", short "No surprise redirects. No broken Back
button.", long "However a site invents ways to throw you to scam pages, Undirect closes them. You just
stay put."

Public copy never names the owner's country or city.

## The product, read from the repo

Cutling keeps snippets of text and images ("cutlings") and types them into any app from its own iPhone
and iPad keyboard; on the Mac a menu bar picker (⌘⇧V) pastes them. Paid once, no account, nothing
leaves the device except the person's own iCloud sync. Live today: 1.6.2 on both platforms.

What 2.0 brings (read from code and commits since 1.6.2; the full list is
`docs/aso/events/changes-since-1.6.2.txt`; check anything against the code in `Cutling/`,
`CutlingKeyboard/`):

- **Variables** (the app's own word; the editor's bar button says "Variables"). A cutling can hold
  blanks filled in each time it is used ("Ask Each Time", for example a name), a choice between options
  (for example a plan), today's date, a time, tomorrow, yesterday, a week from now, the clipboard's text,
  and where the cursor ends. They show as pills in the text (`Cutling/FillInKinds.swift`). On iPhone and
  iPad the Cutling keyboard asks for each blank as it types, with values used before one tap away, and a
  word typed first fills the first blank. On the Mac, picking the cutling with ⌘⇧V opens a short form
  for the blanks before it pastes. Braces typed by hand stay text.
- **Formatted text, written like Notes.** On iPhone and iPad the cutling's text opens as a page that
  works like Apple Notes: a bar with Aa, Variables, Bold, Italic, Strikethrough, Monospace and Link.
  Underline, highlight and bulleted, dashed and numbered lists are being built for 2.0 now (session
  cutling-format; ask nothing, write them as included). Cutlings already kept bold, links and code since
  1.6.0.
- **Far more room.** 5,000 text cutlings and 500 images, up to 10,000 characters in each cutling (1.6.2
  allows 100 text, 25 images, 1,000 characters).
- **Every key types.** On the keyboard, tapping a formatted cutling types it like any other; touching and
  holding it copies it with its formatting.
- **A remade setup guide and a What's New sheet** on iPhone and iPad.

The current English What's New drafts, now out of date (they say "Add Fill-in or Date", which the
editor no longer says): `fastlane/metadata/en-US/release_notes.txt` (iPhone and iPad) and
`fastlane/metadata_mac/en-US/release_notes.txt` (Mac). Each platform's text covers only what that
platform's 2.0 changes over its live 1.6.2; never put a Mac-only item in the iPhone text or the reverse.

## What Apple publishes about event text (facts)

From `docs/aso/in-app-events.md`: name up to 30 characters in title case; short description up to 50,
long description up to 120, both in sentence case; no all capitals, no multiple punctuation; "Don't
include specific prices in your metadata"; "All event metadata must be accurate and pertain to the event
itself". The badge shown above the name is "MAJOR UPDATE". The What's New field holds up to 4,000
characters.

The event will probably run while Cutling's Black Friday sale is on (Nov 27 to 30, 40% off). Whether the
event mentions the sale is the owner's call, so write the event text both ways: one that does not
mention it, and one that does without naming a price.
