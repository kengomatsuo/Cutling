# Where the control that inserts a variable sits in a snippet editor (card ASG108)

Question: where do real products put the control that inserts a blank, today's date, the cursor spot or the clipboard while someone writes a snippet, so Cutling's "Add Fill-in or Date" control is where people look? All fetched 2026-11-21 in this run. Every image is a vendor or Apple file taken from the product's own help page, release notes or App Store listing (App Store images through the iTunes lookup JSON saved in `pages/lookup_<id>.json`); the saved page text is in `pages/`; `notes.md` has the row list. Anything not seen in a picture or not in a saved page is marked GUESS or UNSURE. Chrome was used read-only in one own tab (closed at the end).

Cutling today (read, not changed): `Cutling/TextDetailView.swift`, `placeholderMenu`, a Menu row below "Paste from Clipboard" in the Text section. Off screen below the iPhone text box, off screen on the Mac window until scroll.

## Patterns that repeat

1. Every Mac snippet editor has ONE visible insert control tied to the text box edge, never inside a scrolling list: above the box (Snippety row 2, Typinator row 7), below the box (aText row 6, Alfred row 4 bottom left, Raycast row 9, bottom inside the box), or a side panel (Text Blaze row 10). None sits below other form rows.
2. The label is a noun or a brace glyph: "Insert Placeholder", "Smart Element", "Insert", "Fill-ins", `{ }`. The date, the clipboard and the cursor spot sit in the same list as the blank, not separate controls (Typinator menu row 8; TextExpander toolbar "Fill-ins, Date, Time, Math, Keyboard, Cursor" in the release notes).
3. The control inserts at the caret and the token appears in the text at once; the token is a coloured pill or tag with an icon in the better ones (Snippety, aText, Text Blaze), plain braces in the minimal ones (Alfred, Typinator, Raycast, where valid braces go blue).
4. A one-line hint next to the control names a few examples (Alfred row 4, Raycast row 9).
5. On iPhone the one product that says so ships the placeholder button above the keyboard (Snippety release notes) and recent-first ordering; Apple's Shortcuts does the same with its Variables bar.
6. Fill-in forms appear when the snippet is used, not when it is written (rows 12, 13, 14).

## Apple's own pattern, stated plainly

When you are typing text that can hold a variable, Apple puts the variable control in a bar directly above the keyboard (Shortcuts: the Variables bar, with the special variables like Clipboard and Current Date right in it and "Select Variable" to reach the rest), inserts at the cursor, and shows the result as a blue pill inside the text. On the Mac Apple uses a context menu in the field (Insert Variable). Elsewhere Apple does not insert tokens: Reminders and Notes turn typed words blue or purple, and show date and time as rows under the text (rows 15, 16). The Reminders quick card keeps its three-icon pill at the bottom left under the text (row 16). The keyboard-bar claim for Shortcuts rests on Apple's help text; I found no picture (UNSURE how it looks).

## Two placements for Cutling

iPhone (and iPad with a keyboard on screen): move "Add Fill-in or Date" into a button on the keyboard's accessory bar, shown while the text box is focused, labelled with the same words or the `{ }` mark, opening the existing menu (Fill-in, Date, and the cursor spot / clipboard if Cutling offers them). It is where Apple's Shortcuts puts it (Apple help text) and where Snippety's iOS release notes put it, and it is next to the caret like the Reminders bar in `images/appstore-reminders-quick-reminder-bar.png`. Show the inserted token as a tinted pill with a small icon, as in `images/appstore-snippety-iphone-1.png`. The row below "Paste from Clipboard" stays as the fallback for when the keyboard is hidden (GUESS).

Mac: put a button row directly UNDER the text box inside the Text section, always visible without scroll, with the label "Add Fill-in or Date" and the menu on click, like Alfred's `{ }` button and hint line under the box in `images/alfred-snippet-editor-plain.png`, or one row above it as in `images/snippety-mac-editor.png`. Also keep it as an Insert Variable-style item in the text field's context menu, Apple's Mac pattern (Apple Mac help text). If the editor grows taller than the window, pin the row to the window's bottom edge so it stays visible (GUESS, needs a try in the app).
