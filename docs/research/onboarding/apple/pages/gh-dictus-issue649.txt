Rebuild onboarding for 2.0.0: redesign, Smart Modes, voice notes, and guided setup videos
> **One issue for the whole onboarding.** It replaces #450 (onboarding v2), #494 (teach the Smart Modes during the trial) and #451 (Apple Intelligence readiness on the polish step), which are closed in favour of this one.
>
> **Decided by Pierre on 2026-10-04: this gates 2.0.0, before #279.** The 2.0.0 App Store listing (#643) sends new users straight into onboarding. With the reverse trial live, onboarding is where they have to discover what Pro does. If they don't, the 14 days run out unused.
>
> **Grilled with Pierre on 2026-10-05. The decisions below are the spec.** Budget: about two weeks; Pierre takes it out of the 2.0.0 gate himself if it overruns.

## Current flow (`DictusApp/Onboarding/`, ~2 000 lines)

`WelcomePage` → `MicPermissionPage` → `KeyboardSetupPage` → `PolishTogglePage` (only when `PolishAvailability.isToggleVisible`) → `ModelDownloadPage` → `GlobeKeyTutorialPage` → `OnboardingSuccessView`. Then the trial announcement sheet (#593) is raised automatically for a new user (`ProTrialCoordinator.onboardingCompleted()`). The animations are drawn in SwiftUI; there is no video and no AVKit anywhere in the app. `UIBackgroundModes` already contains `audio`.

Two defects found while grilling, fixed by PR A:
- The keyboard language defaults to `fr` for everyone (`SharedKeys.language`), so an English or German user starts on a French AZERTY keyboard.
- The recommended model depends on the device only (`ModelInfo.recommendedIdentifier`), never on the language, so a Chinese speaker is recommended Parakeet, which does not speak Chinese.

## Decisions

**The journey**

1. The order (**revised 2026-10-06** after the competitor review, see the comment of that day):
   1. Animated intro, three scenes (decision 15; story revised 2026-10-07 in #667: walking, metro without network, the keyboard in Notes)
   2. Language and keyboard. **The model download starts when this screen is confirmed.**
   3. Keyboard in iOS Settings, with a Picture in Picture video
   4. Apple Intelligence, only if it is not ready
   5. Feature videos (decision 9). **The Smart Modes video is followed directly by the pick of three Smart Modes** (decision 16, moved there on 2026-10-07), then voice notes, vocabulary, history
   6. Wait for the model, only if it is still downloading or compiling
   7. Microphone (decision 17)
   8. First dictation through the globe key, in three states: before the field is tapped (a looping drawing of the globe long-press), Apple's keyboard open (a banner above it), Dictus's keyboard open (a banner pointing at the mic). The app cannot draw over the system keyboard, so every hint sits above it.
   9. How to stop Dictus from the Dynamic Island (decision 19)
   10. Completion
   11. The trial announcement, unchanged and automatic
2. **The polish page leaves onboarding.** Polish stays off by default (already the default) and is discovered in Settings. Existing users who turned it on keep it. Why: Parakeet is already clean, polish adds seconds to every dictation, and a new user judges Dictus on speed.

**Language and model**

3. **The language screen** is prefilled with the iPhone's language, so for most users it takes one tap. The keyboard language and its default layout follow it (`SupportedLanguage.defaultLayout`), and the layout can be changed on the same screen (AZERTY / QWERTY / QWERTZ). If the spoken language has no Dictus keyboard (Chinese, for example), a second line asks for the keyboard language among the supported ones, and the transcription language is set explicitly (#226). The screen says this can be changed later. Several languages are set up in Settings, not here.
4. **One model, no choice in onboarding.** The recommendation becomes a rule on **language + device**, in DictusCore with unit tests:
   - a language Parakeet v3 covers, on a device with 6 GB or more → Parakeet;
   - any other language → the best Whisper the device runs reliably (check which variant before choosing; the turbo has a history, #144);
   - pre-A14 devices → today's rule.

   The screen says the model is the best one for the user's language and iPhone, and can be changed in Models. Why: offered a choice, users take the lightest model instead of the best one.
5. **The download runs on any network, without asking.** The size is shown in small type and blocks nothing. Why: "wait for Wi-Fi" is a lost user.
6. The download must survive the user leaving for Settings, and iOS killing the app when Full Access changes. It runs on a background `URLSession` (`BackgroundModelDownloadService`) that resumes after an interruption (#449). **The compile must not start while the app is in the background** (#472). Device validation covers that kill.

**Apple Intelligence step**

7. It is shown only on a capable device where Apple Intelligence is not ready.
   - It gives the exact Settings path. There is no public deep link to the Apple Intelligence page, private `App-Prefs:` URLs get rejected, so the only link is `openSettingsURLString` plus the written path.
   - It warns that **the Siri language must match the device language**, which Apple's support page still requires on iOS 27.
   - It re-checks `availability` when the app comes back. It promises no duration: Apple's model is up to 8 GB and can take from minutes to hours.
   - It can always be skipped.
   - Reported Apple bug: turning Apple Intelligence off can read as `modelNotReady`, so the copy must not depend strictly on the reason.

**Feature videos**

8. One video per screen with **Next**, plus a discreet **Skip** that jumps the whole sequence. Next is never blocked by a video, only by the model. No live Smart Mode demo: Apple Intelligence is often not ready during onboarding.
9. The order:
   1. Smart Modes
   2. Voice notes. The video ends with **adding Dictus to the share sheet's favourites** (Share → More → Edit → +). No API exists to do this for the user.
   3. Vocabulary
   4. History with search (#621)

**Picture in Picture**

10. One day of spike. **The PiP content is a checklist drawn in code, not a recorded video** (revised 2026-10-06): Wispr Flow's floating guide over Settings is a dark card listing the steps ("Keyboards → turn on Full Access → Allow → come back"). The checklist is rendered frame by frame into an `AVSampleBufferDisplayLayer` (`AVPictureInPictureController.ContentSource(sampleBufferDisplayLayer:playbackDelegate:)`, iOS 15+). It plays inline, and tapping **Open Settings** sends it into PiP (`canStartPictureInPictureAutomaticallyFromInline`).
    - Apple requires PiP to start from a user action, never programmatically; that tap is the action.
    - The PiP stops by itself when Full Access is detected, as Wispr Flow's does.
    - The spike also measures whether the app, backgrounded under PiP, can tick each line as it is done. If not, the checklist stays static.
    - It uses a silent `.playback` session with `.mixWithOthers`, and is checked against the recording session.
    - If it does not hold, the fallback is the same checklist animation played in the app, plus the existing detection of the return from Settings.

**Reuse**

11. **What's new for existing users:** at the first launch of 2.0.0, they see the same feature-video sequence once, without the setup steps, then the existing trial announcement (the `.existingUser` kind). It needs a "last version seen" key, which does not exist yet.
12. ~~**The same videos sit on the Pro hub cards (#216).**~~ One feature-video component, used in three places: the onboarding, What's new and ~~the hub~~ the Pro feature screens.
    - *Amended 2026-10-22 (Pierre's decision, #686 / PR #743): the scenes are not in the hub cards. The hub stays as it was (#216); each Pro feature screen has a "How it works" card whose "See the demo" link opens the onboarding scene in a sheet.*

**Design and production**

13. **Mock-ups first, in Pencil, before implementation.** The direction was chosen on 2026-10-06 from Pierre's recordings of three competitor onboardings (Wispr Flow, Superwhisper, Typeless), which stay out of the public repo:
    - **It follows the system appearance, like the rest of the app** (revised 2026-10-06, was forced light). Light is the app's own grouped grey background (`#F2F2F7`) with white cards, exactly like every other screen of the app (revised 2026-10-06 after capturing the real app: the "pure white" this line used to assume does not exist in the app); dark is the app's dark (`#0A1628`). Both cost nothing extra because every animation is drawn in code (decision 14). Mock-ups show both.
    - Superwhisper's visual language, on the app's own colours: large Liquid Glass buttons, large iPhone mock-ups that are cropped (never shown whole) and animated.
    - **The onboarding shell is new; the app's screens are not redesigned** (decided 2026-10-06). A screen that exists elsewhere in the app (model preparation, the keyboard and its Smart Mode fan, the voice-note reader, Vocabulary, History) is shown as it is today. An onboarding-specific variant is allowed, named as such and approved by Pierre. Only iOS system UI (Settings, the Picture in Picture card, the Dynamic Island, the Lock Screen, the globe menu) is drawn.
    - The first dictation through the globe key keeps its mechanics; only its look is reworked.
14. **Motion design in code, not recorded videos** (revised 2026-10-06, replaces the 12 Screen Studio clips). Superwhisper's onboarding has no recordings: its screens are drawn mock-ups (a keyboard of grey blocks, fake toggles, a fake Settings page, a Dynamic Island) animated inside the screen, which is why the screen and the mock-up read as one interface.
    - Every "video" in this issue (keyboard Settings, Apple Intelligence, Smart Modes, voice notes with favourites, vocabulary, history) is a looping SwiftUI animation of drawn mock-ups, 10 to 20 s, silent.
    - Colours come from the app's palette, so light and dark come free; the text inside the mock-ups is localized, so FR and EN come free too.
    - A Screen Studio recording is the fallback only for a scene that cannot be drawn, recorded in light mode.
    - The cost moves from Pierre's recording time to implementation: about half a day to a day per scene, six to eight scenes. It is the heaviest item of PR B and C; Pierre takes it out of the 2.0.0 gate if the two-week budget overruns (as stated at the top).
    - "Feature video" in decisions 8, 9, 11 and 12 now means one of these animated scenes; the shared component (decision 12) plays animated scenes, not files.

**Added 2026-10-06, after the competitor review**

15. **An animated intro replaces the static Welcome**, two or three scenes in the spirit of Wispr Flow's opening carousel: the hand-drawn marker-style woman from the App Store screenshots (#643) walks, dictates, then the hand-drawn Dictus keyboard appears briefly. The art already exists and is drawn in code: the walking woman (`assets/appstore/art/v1x-B/`, merged into #643's branch) and the drawn keyboard (`assets/appstore/art/v10-A/heroSpeak10.ts`, branch `chore/643-hero-a`). The scenes are exported as short looping videos, **one light and one dark render** (the art is code, so the second render costs nothing), and played in the app, so no animation dependency is added. No text baked in.
16. **A "pick your three Smart Modes" step, right after the Smart Modes feature video** (moved on 2026-10-07; it first sat right after the language screen, which asked for a choice before the user had seen what a Smart Mode does). It still falls within the download time. The keyboard's long-press fan holds three modes (`SmartModeCatalogue.maximumPinnedModes`) and the catalogue has more: Structured, List, Message, Summary, and Translate to English, French, Spanish, German (the four `SupportedLanguage` targets, as today). One large card per mode with a one-line explanation; the translation target equal to the language chosen on the language screen is not offered. The choice is written to the pinned list (`SmartModeStore`) and replaces the seed (`defaultPinnedIdentifiers`). Skipping keeps the seed. Hidden on a device that can never run Smart Modes, like the rest of the Pro steps.
17. **The microphone permission moves to just before the first dictation.** It is the moment the user understands why it is needed, and no step before it uses the mic. It keeps a pre-permission screen that says why, so the system popup never appears in the middle of the first recording. `OnboardingStep` persists by raw value, so reordering does not break an onboarding resumed after iOS kills the app.
18. **Refused from the competitors:** account creation (Wispr Flow, Typeless: Dictus has no account, and says so); a hard paywall with prices at the end (Superwhisper, Typeless); setting up the Action Button through Shortcuts (Superwhisper: too heavy for what it gives); a notifications step (Wispr Flow, Typeless).

19. **Show how to stop Dictus from the Dynamic Island, right after the first dictation** (added 2026-10-06, from Superwhisper's tutorial). Many users ask how to turn off the standby (the orange mic indicator). The control already exists: the power button in the expanded standby Live Activity (`StopStandbyIntent`, `DictusLiveActivity.swift`), also on the Lock Screen view. Nobody finds it, so the onboarding shows it.
    - Placed right after the first dictation, which is the moment the standby island appears for real.
    - A looping animation drawn in SwiftUI, not a recorded video: compact island → long press → expanded island with the power button → tap → the island goes away. One sentence of localized text with it.
    - **Dynamic Island devices only.** There is no public API to detect one, so the rule is a table on the model identifier (`DeviceCapabilities` already reads it), in DictusCore with unit tests. It lists the known models **without** an island (notch and Home-button iPhones, iPhone 16e) and treats any unknown identifier as having one, so a future iPhone is covered. Check every recent model against Apple's spec pages before writing the table.
    - Without an island, the same step shows the Lock Screen version of the button instead.
    - ~~It is also part of What's new for existing users (decision 11), since they are the ones asking.~~
    - *Amended 2026-10-22: no longer in What's new. Decided on 2026-10-14 after testing PR #741 (#685, commit 56bf6bb0): stopping the standby from the island has existed since the first version, so it is a reminder for new users in the onboarding, not news for existing ones.*

## Translate needs a language download: where it lands in the onboarding (from #648)

#648 (Translate renders the spoken draft word by word) is moving Translate off the Apple FM prompt onto Apple's Translation framework (`TranslationSession`, `.highFidelity`). Device-measured on 2026-10-06: it runs in the keyboard (4.2 s, ~22 MB) and fixes the worst meaning errors. Details on #648.

What this changes for decision 16 (pick your three Smart Modes):
- The framework only translates a language pair **already installed** on the iPhone. Downloading one shows a system prompt, so it must start from DictusApp, never the keyboard.
- When the user pins a `Translate to …` mode in the pick step, that is the moment to start the download of *chosen language → target*, the same way the model download starts from the language screen. It falls within the time the model is downloading.
- Skipping, or pinning no Translate mode, downloads nothing. A user who adds a Translate mode later gets the same download from Settings (handled in #648's step 3).
- Until the pair is installed, Translate keeps working on the current Apple FM path, so nothing in the onboarding blocks on it.

This adds no screen: it is one call behind the pick step. #648's step 3 owns the download component; this issue only calls it.

Follow-up to the Translate download comment above (#648), decided with Pierre on 2026-10-07 and drawn in the mock-ups as state **06b** of the pick step:

- **One prompt, when the user taps Continue** on the pick step and at least one `Translate to …` mode is pinned. Never one prompt per chip.
- **Dictus warns first, then iOS asks.** A Dictus sheet comes before Apple's `prepareTranslation()` confirmation. It says what the download brings (a more faithful translation, offline), names the pair and its size, and offers **Download** or **Later**. **Later** blocks nothing: Translate keeps the Apple FM path, and Settings offers the download afterwards (#648 step 3).
- **Size: about 105 to 110 MB for French → English, to confirm on a device.** Read in Apple's translation catalogue on the Mac (`com_apple_MobileAsset_SpeechTranslationAssets7`). It is the catalogue the translation daemon actually uses: `translationd`'s own `LastOfflineAssetCatalogUpdate` (2025-09-14 12:11:54) is the catalogue's `lastTimeChecked`, and through it the Mac reports fr → en, fr → es and fr → de as `installed`. English, Spanish, German, French, Italian, Portuguese and Dutch form **one model family**: about 110 MB in full, 51 to 57 MB per language half. A second target in the same family therefore costs little more. Not measurable on a simulator: the iOS 27 simulator answers `unsupported` for fr → en. Still to confirm on a device: the iOS sizes, and whether `.highFidelity` adds anything on top (it uses the Apple Intelligence model, which the user may already have).

## Correction to my 2026-10-07 comment: Translate needs no language download

That comment said pinning a `Translate to …` mode in the pick step (decision 16) should start a language-pair download. It should not.

- Translate now runs on Apple's Translation framework with the `.highFidelity` strategy (#648, PR #672). Apple's documentation states that its models are already present when Apple Intelligence is enabled, so no language download is required.
- Measured: all 64 pairs report `installed` in `.highFidelity` on the Mac, and on the iPhone they stay `installed` even after deleting every language in the Translate app.
- Translate already requires Apple Intelligence, so in shipping conditions there is never anything to download. The download component and the "language not installed" notice were removed from PR #672 on 2026-10-09.

For the onboarding, the Smart Mode pick step only writes the pinned list. It has nothing to download.
